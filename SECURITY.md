# 🔒 Безопасность

## Модель угроз

Бот даёт управлять Codex на твоей машине из Telegram. Codex выполняет команды **с правами пользователя, под которым запущен бот** (режим full access, без подтверждений). Поэтому:

- бот обслуживает ровно одного человека — `TELEGRAM_OWNER_ID` — и только в личном чате. Сообщения других людей, групп и ботов отбрасываются до любых действий: скачивания, расшифровки, вызова Codex;
- кто получил доступ к твоему Telegram-аккаунту, тот получил доступ к машине. Включи в Telegram двухэтапную проверку (Настройки → Конфиденциальность → Облачный пароль);
- не запускай бота от `root`, если можно завести обычного пользователя: так последствия ошибки агента меньше.

## Секреты

- Токен бота, ключ OpenAI и прочее хранятся только в `.env` (права `600`, файл в `.gitignore`). В репозитории лежит только `.env.example` без значений.
- Бот вырезает известные ему секреты и всё, похожее на токен Telegram или ключ `sk-...`, из логов и сообщений.
- Файлы `.env*`, `auth.json`, SSH-ключи, содержимое `~/.ssh` и кэша Local Bot API, а также небольшие файлы, в которых встречается токен или ключ, бот в Telegram не отправляет, даже если агент на них сослался.
- Входящие файлы и расшифровки — недоверенные данные: они сохраняются под сгенерированными именами в `~/.codex-telegram/files`, Codex получает путь и предупреждение.
- `npm run doctor` не печатает значения секретов.

## Если токен утёк

1. [@BotFather](https://t.me/BotFather) → `/revoke` (или в мини-приложении: бот → API Token → Revoke) → новый токен в `.env`.
2. Ключ OpenAI удали на [platform.openai.com/api-keys](https://platform.openai.com/api-keys) и создай новый.
3. Перезапусти бота.

## Как сообщить об уязвимости

Не создавай публичный issue. Используй **Security → Report a vulnerability** в этом репозитории: приватный advisory видит только мейнтейнер.
